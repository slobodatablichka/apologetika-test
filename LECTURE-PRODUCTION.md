# LECTURE-PRODUCTION — единый цикл создания учебных модулей

**Редакция 1.0 · 10 октября 2026 г. · Статус: рабочий производственный план.**

## Цель и единица результата

Быстро выпускать для каждой лекции преподавателя **один работоспособный учебный модуль** на существующем статическом сайте: дикторская лекция + синхронный показ слайдов + доступный текст + итоговый тест. Не откладывать первый выпуск ради построения сложной исследовательской системы.

Один модуль считается готовым, когда его можно открыть по адресу GitHub Pages, прослушать со сменой слайдов, поставить на паузу/перемотать и пройти тест с результатом и разбором ошибок. Озвучка обязательна для итоговой приёмки; прототип без звука не считается готовым модулем.

## Область применения

Один и тот же цикл применяется к наличным **11 лекциям** с сохранением исходных номеров: **1, 3, 4, 5, 6, 7, 8, 9, 10, 11, 13**. Номера **2** и **12** не заполнять предположениями. Три дополнительных документа — самостоятельные материалы; выпускать на их основе отдельные модули только по решению пользователя.

Первая производственная единица и образец — **тема 1**. После её проверки используется тот же шаблон, без повторного проектирования архитектуры.

## Повторяемый сценарий: 8 шагов на каждую тему

1. **Инвентаризация.** Установить исходный DOCX, его идентификатор SRC, структуру разделов, контрольные вопросы и подходящие фотографии слайдов. Зафиксировать точные имена файлов; не смешивать порядок файлов с порядком лекций.
2. **Смысловая карта.** Для каждого подраздела записать ключевые тезисы и обязательные определения, аргументы, примеры и выводы. Отметить авторские оценки и фактические утверждения, требующие проверки. Это краткий рабочий чек-лист, а не самостоятельный большой научный труд.
3. **Дикторский текст.** Переписать материал для устного восприятия: сократить повторы и тяжёлые синтаксические обороты, но **не терять ни одного существенного смысла** из карты. Сохранять отличие позиции преподавателя от установленного факта. Проверить терминологию и произношение.
4. **Сценарий слайдов.** Привязать реальные фотографии к смысловым фрагментам дикторского текста. Если подходящего слайда нет, использовать простой текстовый экран. Не добавлять к лекции сомнительно относящиеся изображения ради заполнения.
5. **Аудио.** Сгенерировать русскую озвучку по разделам; прослушать контрольные отрывки, исправить ударения, имена, богословские термины и паузы; при необходимости пересоздать фрагменты.
6. **Синхронизация.** По фактической длительности аудиофрагментов задать временные метки смены слайдов. Собрать статический веб-проигрыватель: воспроизведение, пауза, перемотка, выбор раздела; текст лекции доступен отдельно. Не требуется MP4, сервер или личный кабинет.
7. **Проверочный тест.** Разработать по смысловой карте банк вопросов, для публикации — итоговый тест ориентировочно **20 вопросов** (фактический объём устанавливается по содержанию темы). Каждый ответ с понятным разбором и ссылкой на подраздел. Не использовать спорные тезисы как бесспорные ключи. Не изменять самостоятельный преподавательский тест из 48 вопросов.
8. **Проверка и выпуск.** Проверить целостность смыслов, корректность слайдов/таймингов/звука, работу управления и теста на компьютере и телефоне; опубликовать модуль в отдельном разделе GitHub Pages; отметить завершение в реестре. Затем перейти к следующей теме.

**Приоритет выполнения:** работоспособность → содержательная полнота → качество воспроизведения → улучшение оформления. Не расширять объём производства без пользы для запуска.

## Минимальный состав данных одного модуля

- Исходный DOCX остаётся неизменным.
- Краткая карта смыслов и связей со слайдами.
- Отредактированный дикторский текст.
- Обработанные изображения слайдов и/или лаконичные текстовые экраны.
- Аудиофайлы по подразделам.
- Сценарий синхронизации (временные отметки для реального аудио).
- Тестовые вопросы с ключами и объяснениями.
- Готовая веб-страница модуля и отметка проверки.

Конкретные пути файлов и формат данных утверждаются при реализации темы 1. **Не создавать сложные форматы, реестры и отдельные инструменты раньше необходимости.**

## Рабочие правила

1. На каждом шаге отдавать проверяемый результат, не заменять выполнение обсуждением перспектив.
2. Существенные сокращения сверять со смысловой картой; отличать авторское изложение от внешней проверки фактов.
3. Связи аудио и слайдов задавать по **готовому аудио**, не угадывать длительность.
4. Если сервис синтеза речи недоступен, явно обозначать ограничение и решать его; не объявлять модуль завершённым без звука.
5. После утверждения темы 1 технология и последовательность считаются типовыми для последующих тем; изменения шаблона — только при практической необходимости.
6. Существующий оригинальный тест преподавателя из 48 вопросов сохранять неизменным и доступным отдельно.
