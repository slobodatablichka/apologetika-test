# Редактирование вопроса в draw.io — прототип

Пробный вопрос: **1.1.1.1**, [открыть файл](1.1.1.1.drawio) через draw.io в режиме GitHub.

**Порядок работы:**
1. Откройте `1.1.1.1.drawio` через draw.io с доступом к `slobodatablichka/apologetika-test`.
2. Дважды щёлкните поле вопроса, ответа или пояснения и измените его текст. В этом образце **три фиксированных ответа**.
3. Правильный ответ обозначается **символом ✓ в начале поля**. При нескольких правильных вариантах ставьте ✓ перед каждым соответствующим вариантом.
4. В нижних полях установите **сложность** числом от 1 до 5 и **номера абзацев DOCX**.
5. Сохраните диаграмму **именно в GitHub, ветка main, тот же путь**. Не переименовывайте и не удаляйте служебные элементы diagram (`question`, `choice_1` и т. д.).
6. GitHub Actions → **Sync draw.io question prototype** выполнит `scripts/sync-drawio-question.py` и сохранит изменение в `tests/lecture-01-bank.json`. Страница `tests/lecture-01.html` читает этот банк и после обновления GitHub Pages покажет новый вопрос.

**Защита:** автоматизация остановится с ошибкой, если отсутствует обязательное поле, нет правильного варианта, есть повторяющиеся ответы или неправильная оценка сложности. Остальные **35 вопросов неизменны**. Каждый синхронизированный вопрос продолжает считаться черновиком до содержательной приёмки.

**Текущие ограничения прототипа:** три поля ответа; изменение их количества и добавление новых вопросов в этом образце ещё не поддерживается. Настройка GitHub Actions должна позволять workflow записывать изменения в репозиторий (`Read and write permissions`); иначе действие не сможет сохранить JSON. Первую сквозную проверку необходимо выполнить после вашего изменения файла в draw.io и посмотреть успешное выполнение workflow. JSON вручную одновременно с draw.io для вопроса 1.1.1.1 больше не редактировать.
