# START — Апологетика: тематические тесты по лекциям

## 1. Назначение проекта

Проект — фрагмент образовательной программы по курсу «Апологетика»: система тематических тестов по готовым лекциям преподавателя и последующей псевдослучайной сборки сопоставимых по сложности вариантов примерно по 50 вопросов. Действующий тест преподавателя на 48 вопросов сохраняется как отдельный независимый модуль.

**Важно:** не смешивать этот проект с:
- сайтом «Практическое руководство для священнослужителя»;
- проектом диафильма/альбома «Апологетика».

Работа относится к учебной системе `apologetika-test`; альбом `diafilm` используется только как возможный источник слайдов для будущих разборов ответов.

## 4. Исходный преподавательский тест — отдельный модуль

В тесте **48 вопросов**.

Типы вопросов:
- `s` — один правильный ответ;
- `m` — несколько правильных ответов.

Режимы прохождения:
1. **Все вопросы по порядку**.
2. **Все вопросы в случайном порядке**.

Правила показа:
- в обоих режимах используются все 48 вопросов;
- варианты ответа внутри каждого вопроса перемешиваются автоматически;
- в случайном режиме дополнительно перемешивается порядок самих вопросов;
- для вопроса с несколькими ответами нужно выбрать весь правильный набор;
- после проверки показывается результат текущего ответа;
- затем пользователь переходит к следующему вопросу.

Во время прохождения показываются:
- номер текущего вопроса из 48;
- прогресс;
- исходный номер вопроса;
- указание: выбрать один ответ или все правильные варианты.

## 5. Исходный тест: итог и оценивание

После завершения теста показываются:
- число правильных ответов;
- процент;
- итоговая оценка;
- количество ошибок;
- подробный разбор ошибок.

Шкала:
- **более 90%** — оценка **5**;
- **75–90%** — оценка **4**;
- **60–менее 75%** — оценка **3**;
- **менее 60%** — оценка **2**.

Для каждой ошибки выводятся:
- номер вопроса;
- формулировка вопроса;
- **Ваш ответ**;
- **Правильный ответ**.

После результата можно пройти тест повторно:
- по порядку;
- в случайном порядке.

## 6. Принятые правила исходного теста на 48 вопросов

1. Канонический объём теста — **48 вопросов**.
2. Режим на 20 случайных вопросов не используется.
3. Два рабочих режима — только:
   - все 48 по порядку;
   - все 48 в случайном порядке.
4. Варианты ответа всегда перемешиваются.
5. Итоговая проверка должна учитывать точное совпадение выбранного набора с ключом.
6. Ошибки разбираются через отдельные блоки **«Ваш ответ / Правильный ответ»**.
7. Шкала 2–5 фиксирована в указанном выше виде.
8. Не менять формулировки вопросов и ключи без отдельного содержательного решения.
9. Основные ключи воспроизведены по предоставленному учебному документу.
10. Вопросы **3, 11, 28, 32 и 46** были восстановлены или уточнены для тренировочного режима; их следует считать отдельной зоной повышенного внимания при дальнейшей содержательной проверке.
11. Не подменять отсутствующий или сомнительный исходный материал общими знаниями без явного решения.
12. Перед изменениями проверять фактическое состояние репозитория, а не восстанавливать его только по памяти чатов.

## 8. Текущий приоритет

Создание **тематического банка вопросов по оригинальному DOCX лекции № 1**, затем по другим имеющимся лекциям. Каждый вопрос привязывается к конкретному материалу оригинальной лекции, снабжается объяснением, исчерпывающим ключом и предварительной оценкой сложности 1–5.

Рабочие регламенты: [`TEST-PRODUCTION.md`](TEST-PRODUCTION.md) и [`TEST-GENERATION.md`](TEST-GENERATION.md). Тексты озвученных лекций, аудио и синхронизация слайдов **не входят в текущую задачу**.

Исходная база — [`APOLOGETIKA-DOCUMENT-PASSPORTS.md`](APOLOGETIKA-DOCUMENT-PASSPORTS.md): 14 документов (11 лекций и 3 дополнительных материала). Тематическая структура — [`CURRICULUM.md`](CURRICULUM.md). Нумерацию и авторство оригиналов сохранять; отсутствующие темы 2 и 12 не придумывать.

## 11. Новые тематические банки вопросов

Количество вопросов в тематическом банке диктуется полнотой охвата лекции, не фиксированной квотой. Количество вариантов в каждом вопросе — **адекватное его глубине**, без обязательной четвёрки. Правильный ответ может быть **одиночным либо совокупностью нескольких выбранных вариантов**; полная правильность множественного выбора — точное совпадение с ключом. Для каждого вопроса обязательны содержательное объяснение решения, проверка каждого варианта, связь с первоисточником и предварительная сложность **1–5**. Не смешивать мнение автора с общепризнанным фактом.

## 12. Псевдослучайные межтематические варианты

Будущие варианты — ориентировочно **по 50 вопросов**. Требуется сопоставимость **средней сложности**, распределения уровней и тематического охвата. Отбор — стратифицированный псевдослучайный из проверенного общего банка с сохранением seed воспроизведения. Пропорции тем, уровней и допуски ещё не утверждены; примеры не являются нормативными значениями. Детали — в `TEST-GENERATION.md`.

## Единый стандарт идентификации (20 октября 2026 года)

**Смысловой элемент** — `L.S.E`: `L` — исходный номер лекции преподавателя; `S` — номер раздела внутри неё; `E` — порядковый номер смыслового элемента в разделе. Примеры: `1.1.1`, `1.1.2`, `1.2.1`, `1.4.3`, `2.1.1`. Число элементов в разделе определяется содержанием и не ограничивается искусственной квотой.

**Вопрос** — `Q-L.S.E-NN`: основной смысловой элемент и порядковый номер вопроса, начиная с `01`. Например: `Q-1.4.3-01`, `Q-1.4.3-02`. ID уникален и не переиспользуется; дополнительные смысловые связи допускаются. При перестановке объектов на схеме или вариантов ответа ID не меняется.

Подлинные номера лекций преподавателя **не перенумеровывать**. Сейчас известны 1, 3–11, 13; исходники 2 и 12 отсутствуют. Образец `2.1.1` обозначает возможный будущий элемент при появлении лекции 2, но не свидетельствует, что её оригинал уже имеется.

## Работа с draw.io

Для каждой лекции допускается **одна основная редактируемая смысловая карта** формата `.drawio` в `maps/` репозитория `slobodatablichka/apologetika-test` (например, `maps/tema-01-smyslovaya-karta.drawio`). В карту включать реальные разделы оригинала и пронумерованные узлы `L.S.E` с понятиями, классификациями и смысловыми связями. По мере выпуска банка приписывать узлам связанные ID вопросов `Q-L.S.E-NN` и при необходимости уровни сложности.

Карта предназначена для **анализа содержания, выявления пробелов и конструирования содержательно сложных вопросов**, прежде всего уровней 3–5. Не создавать отдельный рисунок на каждый вопрос; схема необязательна там, где не добавляет пользы. **Единственным первоисточником остаётся оригинальная лекция**, а канонические формулировки, ключи, объяснения, сложность и статусы хранятся в структурированном банке вопросов, не в рисунке.

Диаграммы правятся через draw.io/diagrams.net с GitHub-интеграцией или как корректный `.drawio` XML и сохраняются в GitHub. Не объявлять визуальное содержимое схемы проверенным без сверки с исходным DOCX. Изменение карты не должно автоматически менять идентификаторы или утверждённые ключи вопросов.
