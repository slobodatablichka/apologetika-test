# TEST-PRODUCTION — создание тематических тестов

**Редакция 3.0 · 21 октября 2026.** Краткий обязательный производственный регламент. `START.md` читается первым.

## 1. Источник и структура

Первичный материал — полный оригинальный DOCX преподавателя либо проверенная полная текстовая копия с возможностью сверки. Не придумывать недостающие части. Сохранять исходные разделы; аналитические блоки выделять по реальным смысловым связям. Нумерация: `L.S.B.Q` (лекция, раздел, блок, вопрос). Ранее опубликованные ID не перенумеровывать.

Из содержания выделять ключевые определения, различения, аргументы, возражения, примеры и выводы. Один вопрос может проверять несколько связанных положений; фиксированного числа вопросов на блок нет. Ориентир 30–40 вопросов на лекцию, максимум 50.

## 2. Вопрос и варианты

- Каждый вопрос **самостоятельный**: не ссылаться на лекцию, составителя или фразу «по тексту». При проверке взглядов точно называть мыслителя; спорные утверждения не выдавать за бесспорные.
- Примерно половина вопросов — множественного выбора (цель 45–55%, рабочий коридор 40–60% с обоснованием). Для множественного выбора нужны минимум два правильных и один неверный ответ. Квота не оправдывает искусственных заданий.
- **Сначала** определить предмет проверки и исчерпывающий правильный набор. **Затем** составить правдоподобные, но однозначно ошибочные дистракторы. Каждый вариант оценивать независимо.
- Число вариантов выбирается содержательно. Не применять одинаковый рецепт для всех одиночных или всех множественных; не строить массово «3 правильных + 1 неправильный». Не добавлять слабый вариант только ради разнообразия.
- Неверные варианты должны конкурировать с верными по тематике, форме и убедительности, но не быть двусмысленными или частично верными. Не пользоваться очевидным абсурдом, посторонней предметной областью, необоснованными «всегда / исключительно / никогда» и визуальными подсказками.
- Ключи не должны выстраиваться в угадываемую последовательность. Перестановка вариантов не заменяет содержательную правку.
- Сложность **1–5**: 1 — узнавание; 2 — воспроизведение; 3 — различение/связи; 4 — сопоставление доводов; 5 — комплексный анализ. Она зависит от мыслительной задачи, а не числа вариантов.

## 3. Банк и разбор

Запись вопроса включает `id`, `section`, `block`, локатор источника, `question`, `options` с устойчивыми ID, `correct` (полный набор), `explanation`, `difficulty` и `status`.

Тест проверяет точное совпадение выбранного набора с ключом. После ответа показывает короткое объяснение; при ошибке — неверно выбранные и пропущенные правильные варианты, без лишнего дублирования. Опционально хранить пояснения для каждого варианта. Исходный тест преподавателя на 48 вопросов не менять.

## 4. Проверка и приёмка — без лишних процедур

1. Сверить **весь банк**, а не только изменённые вопросы, с первоисточником. Проверить формулировку, **каждый** вариант, исчерпывающий ключ, объяснение и оценку сложности.
2. Одной сводкой показать распределение типов, числа вариантов, количества и расположения правильных ответов, уровня сложности. Найти механические шаблоны, повторы, сомнительные ключи. Исправлять содержательно, а не ради числовой симметрии.
3. Проверить покрытие значимых смыслов оригинала; особое внимание — близким понятиям и спорным положениям.
4. Проверить уникальные ID, JSON, HTML, интерфейс, навигацию. Карта draw.io должна показывать **понятия, направленные смысловые связи и аргументацию**, а не только номера.
5. При обнаруженной неустранённой ошибке, неоднозначном ключе или неполной содержательной проверке **не объявлять комплект готовым и не публиковать его как исправленный**. Сохранять статус «черновик».

## 5. Выпуск

Готовить и проверять вместе `tests/lecture-NN-bank.json`, `tests/lecture-NN.html`, `maps/tema-NN-smyslovaya-karta.drawio` и необходимые ссылки. Предпочтителен один атомарный коммит, затем проверка файлов в `main` и страницы. При технической блокировке менять способ записи, **никогда не упрощать содержание**.

Итог задачи — качественный учебный тест. Контроль должен быть достаточным для выявления ошибок, но не подменять их исправление.
